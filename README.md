# AVELORA Store

فروشگاه اینترنتی فارسی AVELORA برای عرضه کیف، اکسسوری، لوازم آرایشی و محصولات قابل‌افزایش.

## امکانات پیاده‌سازی‌شده

- نمایش، جست‌وجو و فیلتر محصولات و دسته‌بندی‌ها
- سبد خرید و ثبت سفارش مهمان یا عضو؛ قیمت، تخفیف، موجودی و مبلغ نهایی در سرور دوباره محاسبه می‌شوند
- عضویت رایگان با رمز عبور و تخفیف ۵٪ برای محصولات واجد شرایط؛ تخفیف با تخفیف محصول جمع نمی‌شود و از بهای تمام‌شده پایین‌تر نمی‌رود
- نشست امن مشتری و خروج از حساب
- پنل مدیریت با حساب مالک و حساب‌های مستقل مدیران فرعی
- تعیین مجوزهای جداگانه برای محصولات، سفارش‌ها، مشتریان، پرداخت، حسابداری، گزارش‌ها و سوابق فعالیت
- کنترل دسترسی در سمت سرور؛ فقط مالک می‌تواند مدیر بسازد، مجوزها را تغییر دهد، رمز مدیر را بازنشانی کند یا حساب مدیر را غیرفعال کند
- ثبت رویدادهای ورود و فعالیت مدیران و نمایش نشست‌های فعال فقط برای مالک
- مدیریت محصولات، تصویر، موجودی، قیمت خرید، قیمت فروش و بایگانی
- مدیریت سفارش‌ها و مشتریان با حفظ سوابق خرید
- گزارش فروش و دفتر هزینه‌های دارای سابقه اصلاح
- مرکز ثبت خطاهای API
- دستیار رایگان راهنمای خرید مبتنی بر کاتالوگ واقعی فروشگاه؛ بدون API هوش مصنوعی پولی
- زیرساخت زرین‌پال؛ خاموش به‌صورت پیش‌فرض

## وضعیت انتشار

**این نسخه هنوز برای انتشار عمومی تأیید نشده است.** تغییرات چندمدیره و حسابداری در شاخه آزمایشی `feature/admin-rbac-foundation` و PR شماره ۶ قرار دارند؛ تا پایان بازبینی و تأیید مالک، آن‌ها را با `main` ادغام نکنید.

موانع اصلی انتشار عمومی:
1. تأیید مالکیت شماره موبایل مشتری با پیامک و بازیابی امن رمز عبور هنوز پیاده‌سازی نشده است.
2. دامنه، میزبانی پایدار و HTTPS عمومی هنوز تهیه و پیکربندی نشده‌اند.
3. فضای ذخیره‌سازی پایدار برای `backend/uploads` و پشتیبان‌گیری قابل‌بازیابی از تصاویر و PostgreSQL باید تضمین شود.
4. اطلاعات تماس، شرایط ارسال، مرجوعی، حریم خصوصی و شرایط خرید باید تکمیل و تأیید شوند.
5. بهای تمام‌شده و موجودی واقعی همه محصولات باید بازبینی شوند.
6. زرین‌پال فقط پس از HTTPS، تنظیم امن پذیرنده و آزمون sandbox/callback قابل فعال‌سازی است.

فهرست جزئیات و معیارهای پذیرش در [docs/PRELAUNCH_AUDIT.md](docs/PRELAUNCH_AUDIT.md) آمده است.

## راه‌اندازی محلی در Termux

از پوشه پروژه:

```bash
cd ~/Minimarkettiyam/backend
npm ci
```

پایگاه داده‌ها را بسازید و ساختار کامل نسخه این شاخه را فقط روی دیتابیس تازه ایجاد کنید:

```bash
createdb minimarkettiyam
createdb minimarkettiyam_test

for db in minimarkettiyam minimarkettiyam_test; do
  psql -d "$db" -v ON_ERROR_STOP=1 -f ../database/schema.sql
  for migration in 004_customer_membership.sql 005_admin_rbac.sql 006_accounting_error_center.sql 007_product_image_gallery.sql; do
    psql -d "$db" -v ON_ERROR_STOP=1 -f "../database/migrations/$migration"
  done
done
```

این دستورها برای دیتابیس تازه هستند. برای دیتابیس موجود، فایل‌ها را کورکورانه دوباره اجرا نکنید؛ ابتدا نسخه پشتیبان قابل‌بازیابی تهیه و مهاجرت‌های اعمال‌شده را بررسی کنید.

فایل تنظیمات را از نمونه بسازید:

```bash
cp .env.example .env
nano .env
```

حداقل `DATABASE_URL` و `ADMIN_API_KEY` باید با مقادیر واقعی تنظیم شوند. کلید مدیریت باید تصادفی، محرمانه و حداقل ۳۲ بایت باشد؛ آن را در GitHub، پیام‌ها یا کد قرار ندهید. در محیط production مقدار `TRUST_PROXY` نیز اجباری است و باید مطابق تعداد/محدوده پروکسی‌های مورد اعتماد میزبان تنظیم شود؛ مقدار `1` فقط برای دقیقاً یک پروکسی مورد اعتماد مناسب است. هرگز همه هدرهای Forwarded را بدون محدودیت مورد اعتماد قرار ندهید.

اجرای محلی:

```bash
npm start
```

- فروشگاه: http://127.0.0.1:3000
- پنل مدیریت: http://127.0.0.1:3000/admin/

## مهاجرت‌های پنل چندمدیره و حسابداری

مهاجرت‌های زیر متعلق به شاخه آزمایشی هستند:

- `005_admin_rbac.sql`: حساب مالک، مدیران مستقل، نشست‌ها و سوابق فعالیت
- `006_accounting_error_center.sql`: snapshot بهای تمام‌شده اقلام سفارش، دفتر هزینه‌ها و مرکز خطاها
- `007_product_image_gallery.sql`: گالری چندتصویری محصولات؛ تصویر اصلی فعلی هر محصول را بدون حذف حفظ و به گالری منتقل می‌کند

آزمون یکپارچه این مهاجرت‌ها را روی پایگاه داده آزمایشی اجرا می‌کند. **آن‌ها را روی دیتابیس اصلی اجرا نکنید مگر پس از تأیید نهایی نسخه، تهیه پشتیبان و آزمون واقعی بازیابی.** راهنمای کامل در [docs/ADMIN_ACCESS.md](docs/ADMIN_ACCESS.md) است.

پس از تأیید نسخه و آماده‌شدن محیط عملیاتی، حساب مالک فقط یک‌بار از صفحه `/admin/` ساخته می‌شود. پس از آن ورود روزانه با نام کاربری و رمز حساب مالک انجام می‌شود؛ کلید `ADMIN_API_KEY` را محرمانه نگه دارید.

## عضویت و شماره موبایل

در نسخه فعلی، عضویت با شماره موبایل و رمز عبور انجام می‌شود، اما مالکیت شماره با پیامک تأیید نمی‌شود و بازیابی امن رمز عبور وجود ندارد. بنابراین عضویت و تخفیف ۵٪ نباید بدون تعیین تکلیف این محدودیت به‌عنوان قابلیت آماده انتشار عمومی معرفی شود.

## تنظیم پروکسی و محدودیت درخواست‌ها

در حالت production، مقدار `TRUST_PROXY` باید مطابق معماری شبکه میزبان تنظیم شود تا `req.ip` و محدودیت درخواست‌ها برای هر مشتری جداگانه محاسبه شوند. برای یک reverse proxy مورد اعتماد از `TRUST_PROXY=1` استفاده کنید؛ اگر میزبان چند لایه پروکسی دارد، تعداد hop یا subnetهای دقیق مورد اعتماد را از مستندات همان میزبان تعیین کنید. پروکسی باید هدرهای `X-Forwarded-For` ورودی کاربر را بازنویسی/پاک‌سازی کند. محدودکننده فعلی در حافظه همان پردازش Node.js است؛ تا افزودن ذخیره‌ساز مشترک، فقط یک نمونه backend اجرا شود و برای چند نمونه باید rate limit توزیع‌شده پیاده‌سازی شود.

## پرداخت

- پرداخت کارت‌به‌کارت فقط وقتی در دسترس مشتری قرار می‌گیرد که مالک اطلاعات معتبر را وارد و آن را فعال کند.
- زرین‌پال با `ZARINPAL_ENABLED=false` خاموش است.
- برای محیط عملیاتی، دامنه عمومی HTTPS، `PUBLIC_BASE_URL`، شناسه پذیرنده معتبر و تنظیمات محرمانه لازم است.
- در محیط production، برنامه بدون `DATABASE_URL`، آدرس HTTPS معتبر و کلید مدیریت قوی بالا نمی‌آید.
- موفقیت تست محلی به معنی تأیید اتصال واقعی درگاه نیست؛ آزمون sandbox و سپس آزمون کنترل‌شده production ضروری است.

## حسابداری و گزارش‌ها

- درآمد وصول‌شده فقط از سفارش‌های دارای `payment_status='verified'` محاسبه می‌شود.
- بهای تمام‌شده اقلام از زمان ثبت سفارش snapshot می‌شود؛ برای سفارش‌های تاریخی فاقد این داده، سود قطعی قابل محاسبه نیست.
- دفتر هزینه‌ها ردیف‌های اصلاحی مثبت و منفی را نگه می‌دارد و سابقه حذف نمی‌شود.
- «مانده پس از هزینه‌های ثبت‌شده» سود خالص قانونی نیست و فقط هزینه‌های واردشده را در نظر می‌گیرد.

## بررسی و آزمون

از پوشه `backend`:

```bash
npm run check
npm run test:zarinpal
npm run test:integration
```

آزمون یکپارچه از پایگاه داده جداگانه `minimarkettiyam_test` استفاده می‌کند. هرگز آن را به دیتابیس اصلی متصل نکنید. در این شاخه، آزمون‌های محلی کاربر و GitHub Actions روی PostgreSQL مجزا اجرا شده‌اند؛ پیش از انتشار، آزمون روی محیط میزبانی نیز لازم است.

## پشتیبان‌گیری و فایل‌های محصول

پوشه `backend/uploads/` تصاویر واقعی محصولات را نگه می‌دارد. آن را حذف یا بازنویسی نکنید. در استقرار، این مسیر باید روی فضای پایدار باشد و همراه PostgreSQL پشتیبان‌گیری شود. بازیابی آزمایشی هر دو، معیار پذیرش انتشار است.
