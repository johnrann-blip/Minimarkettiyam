# AVELORA Store

فروشگاه اینترنتی فارسی برای عرضه کیف، اکسسوری، لوازم آرایشی و محصولات قابل‌افزایش.

## امکانات فعلی

- نمایش، جست‌وجو و فیلتر محصولات و دسته‌بندی‌ها
- سبد خرید در مرورگر و ثبت سفارش با محاسبه مجدد قیمت و موجودی در سرور
- جلوگیری از ثبت سفارش تکراری و کنترل هم‌زمانی موجودی
- پنل مدیریت با کلید محرمانه برای محصولات، تصاویر، بایگانی، سفارش‌ها و تنظیمات فروشگاه
- آپلود تصویر محصول با محدودیت حجم و بررسی امضای فایل
- تنظیم تعرفه ارسال داخل شهر و سراسری
- راهنمای خرید رایگان مبتنی بر کاتالوگ واقعی فروشگاه؛ بدون API هوش مصنوعی پولی
- زیرساخت زرین‌پال؛ غیرفعال به‌صورت پیش‌فرض و نیازمند پیکربندی امن پس از انتشار HTTPS

## وضعیت انتشار

این مخزن هنوز به‌تنهایی به معنی آنلاین بودن فروشگاه نیست. پیش از دریافت سفارش واقعی باید میزبانی پایدار، دامنه، HTTPS، کلید مدیریت قوی، پشتیبان‌گیری خودکار از PostgreSQL و پوشه تصاویر، اطلاعات تماس و سیاست‌های ارسال/مرجوعی مشخص شوند. پرداخت واقعی نیز باید جداگانه در محیط تأییدشده درگاه آزمایش شود.

## نیازمندی‌ها

- Node.js 20 یا جدیدتر
- PostgreSQL 14 یا جدیدتر

## راه‌اندازی محلی در Termux

```bash
pkg update
pkg install nodejs-lts postgresql
cd ~/Minimarkettiyam/backend
npm install
```

پایگاه داده اصلی و آزمایشی را بسازید و ساختار را روی هر دو اجرا کنید:

```bash
createdb minimarkettiyam
createdb minimarkettiyam_test
psql -d minimarkettiyam -f ../database/schema.sql
psql -d minimarkettiyam_test -f ../database/schema.sql
```

تنظیمات را بسازید:

```bash
cp .env.example .env
nano .env
```

حداقل این موارد باید با مقادیر واقعی و محرمانه تنظیم شوند:

- `DATABASE_URL`: نشانی اتصال PostgreSQL
- `ADMIN_API_KEY`: کلید تصادفی و محرمانه حداقل ۳۲ بایت؛ آن را در GitHub یا اختیار مشتریان قرار ندهید.
- `PORT`: پورت سرویس؛ مقدار پیش‌فرض 3000 است.

اجرای محلی:

```bash
npm start
```

- فروشگاه: http://127.0.0.1:3000
- پنل مدیریت: http://127.0.0.1:3000/admin/

## تنظیم پرداخت

- کارت‌به‌کارت فقط زمانی در دسترس مشتری قرار می‌گیرد که مدیر آن را در پنل فعال و اطلاعات معتبر را وارد کرده باشد.
- زرین‌پال با `ZARINPAL_ENABLED=false` خاموش است.
- برای محیط عملیاتی، ابتدا سایت باید دامنه عمومی و HTTPS معتبر داشته باشد؛ سپس `NODE_ENV=production`، `PUBLIC_BASE_URL`، `ZARINPAL_MODE=production`، شناسه پذیرنده معتبر و فعال‌سازی آگاهانه درگاه تنظیم شوند.
- در محیط production، برنامه در صورت نبود کلید مدیریت قوی یا پیکربندی ناقص پرداخت فعال‌شده، از راه‌اندازی خودداری می‌کند.
- موفقیت تست‌های محلی به معنی تأیید اتصال واقعی زرین‌پال نیست؛ آزمون sandbox و سپس آزمون کنترل‌شده production ضروری است.

## بررسی و آزمون

از پوشه `backend`:

```bash
npm run check
npm run test:zarinpal
npm run test:integration
```

آزمون یکپارچه از پایگاه داده جداگانه `minimarkettiyam_test` استفاده می‌کند. هرگز آن را به پایگاه داده اصلی متصل نکنید.

## پشتیبان‌گیری

برای انتشار عمومی، پشتیبان‌گیری زمان‌بندی‌شده از پایگاه داده و پوشه `backend/uploads` لازم است. هر دو باید در بازیابی آزمایشی نیز بررسی شوند؛ داشتن فایل backup به‌تنهایی تضمین بازیابی نیست.

## مسیرهای اصلی API

- `GET /api/health`
- `GET /api/categories`
- `GET /api/products`
- `GET /api/store-settings`
- `POST /api/orders`
- مسیرهای `/api/admin/*` فقط با هدر `x-admin-key` قابل استفاده‌اند.
- مسیرهای `/api/payments/zarinpal/*` تا آماده‌شدن تنظیمات امن غیرفعال می‌مانند.
