# مدیریت چندمدیره و آماده‌سازی انتشار AVELORA

## وضعیت و اصل ایمنی

این شاخه هنوز نسخه انتشار عمومی نیست. تغییرات را ابتدا روی پایگاه داده آزمایشی اجرا و آزمون کن. تا پیش از تأیید کامل، مهاجرت‌ها را روی دیتابیس اصلی اجرا نکن و پرداخت واقعی زرین‌پال را فعال نکن.

**مهم:** پیش از هر مهاجرت روی دیتابیس اصلی، نسخه پشتیبان قابل‌بازیابی تهیه و صحت آن را بررسی کن. پوشه `backend/uploads/` شامل تصاویر محصولات است؛ آن را حذف نکن و در استقرار باید در فضای ذخیره‌سازی پایدار حفظ شود.

## مهاجرت‌ها

ترتیب مهاجرت‌های افزوده‌شده:
- `005_admin_rbac.sql`: حساب مالک، مدیران مستقل، نشست‌ها و سوابق فعالیت
- `006_accounting_error_center.sql`: snapshot بهای تمام‌شده اقلام سفارش، دفتر هزینه‌ها با ردیف اصلاحی، و مرکز خطاها

ابتدا روی دیتابیس آزمایشی:
```bash
cd ~/Minimarkettiyam/backend
psql -d minimarkettiyam_test -v ON_ERROR_STOP=1 -f ../database/migrations/005_admin_rbac.sql
psql -d minimarkettiyam_test -v ON_ERROR_STOP=1 -f ../database/migrations/006_accounting_error_center.sql
npm run check
npm run test:zarinpal
npm run test:integration
```

اسکریپت یکپارچه نیز مهاجرت‌های لازم را روی دیتابیس آزمایشی اعمال می‌کند. این آزمون‌ها نباید به دیتابیس اصلی متصل شوند.

## راه‌اندازی مالک و مدیران

پس از تأیید آزمون‌ها و آماده‌شدن نسخه پشتیبان، مهاجرت‌های 005 و 006 را روی دیتابیس اصلی اجرا کن. سپس سرور را با تنظیمات محیطی امن راه‌اندازی کن و در `/admin/` حساب مالک را فقط یک‌بار بساز. کلید `ADMIN_API_KEY` فقط برای bootstrap است؛ آن را در کد، GitHub یا پیام‌ها قرار نده.

هر مدیر حساب مستقل دارد. فقط مالک می‌تواند مدیر بسازد، مجوزها را تغییر دهد، رمز را بازنشانی کند یا مدیر را غیرفعال کند. مجوزهای پرداخت مستقل‌اند:
- مشاهده اطلاعات بانکی و پرداخت
- مدیریت اطلاعات بانکی و پرداخت

مجوزهای مشاهده و مدیریت مشتریان نیز جدا هستند. مشتری دارای هرگونه سابقه سفارش از این صفحه قابل غیرفعال‌سازی نیست. مشتری بدون سفارش فقط به‌صورت برگشت‌پذیر غیرفعال می‌شود؛ سوابق حذف نمی‌شوند.

## حسابداری و گزارش‌ها

- درآمد وصول‌شده فقط از سفارش‌های دارای `payment_status='verified'` محاسبه می‌شود.
- هزینه‌ها در دفتر جداگانه ثبت می‌شوند؛ مبلغ مثبت هزینه و مبلغ منفی ردیف اصلاحی/برگشت است. ردیف‌ها حذف یا ویرایش نمی‌شوند تا رد حسابداری باقی بماند.
- بهای تمام‌شده در لحظه ثبت سفارش در `order_items` ذخیره می‌شود.
- سفارش‌های تاریخی که بهای تمام‌شده آن‌ها ذخیره نشده‌اند، سود ناخالص قابل‌اعتماد ندارند و در گزارش به‌عنوان اقلام فاقد بهای تمام‌شده نشان داده می‌شوند.
- دفتر هزینه‌ها هزینه‌های عملیاتی و ردیف‌های اصلاحی مثبت/منفی را نگهداری می‌کند و گزارش «مانده پس از هزینه‌های ثبت‌شده» را نشان می‌دهد. این عدد سود خالص قانونی نیست؛ هزینه‌های ثبت‌نشده، مالیات، مرجوعی‌ها و هزینه واقعی ارسال باید کامل و جداگانه وارد شوند.
- مرکز خطاها پاسخ‌های 5xx مسیرهای API را ثبت می‌کند؛ خطاهای میزبانی، CDN و خطاهای خارج از API باید از داشبورد میزبان نیز پایش شوند.

## مواردی که پیش از انتشار عمومی باید تعیین تکلیف شوند

1. تأیید مالکیت شماره موبایل هنگام عضویت و فرایند امن بازیابی رمز عبور هنوز نیازمند راهکار عملیاتی است.
2. اطلاعات تماس، نشانی، شرایط ارسال، سیاست مرجوعی، حریم خصوصی و شرایط خرید باید توسط مالک فروشگاه تکمیل و بازبینی شوند.
3. دامنه و HTTPS معتبر، میزبانی پایدار، پشتیبان‌گیری خودکار و روش بازیابی فایل‌های `uploads` لازم است. مقدار `PUBLIC_BASE_URL` نیز باید با آدرس عمومی HTTPS تنظیم شود؛ سرور در حالت production بدون آن بالا نمی‌آید.
4. پرداخت زرین‌پال فعلاً خاموش بماند تا دامنه HTTPS، اطلاعات محرمانه معتبر و آزمون sandbox/تأیید callback تکمیل شود.
5. هزینه خرید همه محصولات باید ثبت شود تا تخفیف عضویت و گزارش سود ناخالص بر پایه اطلاعات واقعی باشند.
6. پس از استقرار، آزمون خرید واقعی با مبلغ کم و بدون دریافت اطلاعات محرمانه در پیام‌ها انجام شود.

## کنترل کیفیت

GitHub Actions در هر Pull Request به `main` و pushهای شاخه اصلی/این شاخه، دیتابیس PostgreSQL مستقل می‌سازد و `npm ci`، `npm run check`، `npm run test:zarinpal` و `npm run test:integration` را اجرا می‌کند.

دستورهای محلی:
```bash
cd ~/Minimarkettiyam
git checkout feature/admin-rbac-foundation
git pull origin feature/admin-rbac-foundation
cd backend
npm run check
npm run test:zarinpal
npm run test:integration
```

هیچ رمز، کلید API، کوکی نشست یا اطلاعات بانکی را در ترمینالِ قابل‌اشتراک، گزارش خطا یا پیام ارسال نکن.
